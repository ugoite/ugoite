---
title: "Ugoite v0.2.0 — Product UX across Browser and CLI"
---

Ugoite v0.2.0 completes a broad Product UX pass over the existing Knowledge
Foundation. Browser and CLI workflows now share clearer contracts for Forms,
structured Entries, search, Saved SQL, and recovery. Knowledge-to-tools remains a
future direction and is not part of this release.

## Highlights

- Browser navigation centers work on Forms and their Entries, with a consistent
  Entry table, clearer task context, and more direct recovery and validation
  feedback.
- Entry authoring and reads use structured fields. Search and filtering use the
  canonical EntryQuery contract across the Browser, local CLI, and remote API.
- Saved SQL has a complete Browser and CLI lifecycle, with stateless query
  execution and no server-side SQL session requirement.
- CLI contexts provide a consistent way to select a connection and Space, and
  mutation output uses durable receipts that are easier to inspect and automate.
- Shared Rust behavior keeps local and remote operations aligned while Spaces
  remain user-owned and portable.

## Breaking changes

This is a pre-1.0 breaking release. The CLI and API remove transitional v0.1
compatibility surfaces; scripts and integrations may need to move to the
canonical context, structured Entry, EntryQuery, Saved SQL, and mutation receipt
contracts. Browser navigation aliases and whole-Entry raw Markdown authoring are
also removed. Check `ugoite <command> --help` for CLI syntax and the server's
`/openapi.json` for the REST contract before updating automation.

## Upgrade

- Review the [Upgrade and Compatibility guide](../../operate/upgrade-compatibility.md)
  and preserve the configured Space and control-store locations and node secret.
- Update scripts and integrations for the breaking CLI and API contracts before
  relying on them with v0.2.
- No new Space authority or storage semantics are introduced by the Product UX
  work; Knowledge-to-tools and browser-local persistence remain future work.
