title: "v0.2 product capabilities"
---

**Status:** v0.2.0 published

**Active authority:** Product UX is the sole active v0.2 release authority. The
v0.1 Foundation remains frozen. v0.2 makes existing durable Knowledge
capabilities usable without changing ownership or authority of user data.

Shipped in v0.2.0, as recorded in the immutable
[v0.2.0 release note](../../version/releases/v0.2.0.md):

- Form-first Browser navigation;
- structured Entry authoring and reads;
- canonical EntryQuery search and filtering across Browser, local CLI, and
  remote API;
- Saved SQL lifecycle and stateless SQL query execution;
- CLI Context selection and durable mutation Receipt output;
- shared Rust behavior across local and remote operations.

The release note and implementation establish these shipped capabilities.
Broader Product UX acceptance criteria without direct evidence remain
unverified follow-up work in [`product-ux.yaml`](../../version/v0.2/product-ux.yaml);
they are not represented as completed merely because v0.2.0 was published.

Knowledge-to-tools remains a North Star, not a shipped v0.2 acceptance claim.
Portable View/Application Definitions, Knowledge-to-tools renderers, broader MCP
resources beyond the small stable v1 facade, and vector, voice, and other
AI-assisted workflows remain future/reference scope and are not active v0.2
acceptance criteria.

Definitions that become durable remain ordinary Space-owned Knowledge. Rendered
state, transient query results, and execution state remain Experience runtime
state. v0.2 does not assume arbitrary JavaScript/Python execution, package
installation, an app-specific backend/database, or a parallel authorization
authority.

None of these items is shipped merely because it appears in a roadmap. The
current browser remains server-backed; browser-local Space persistence and
optional synchronization/relay behavior remain planned, not shipped. MCP v1
remains the small stable semantic facade described in `../api/mcp.md`.
