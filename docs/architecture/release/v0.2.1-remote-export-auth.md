This acceptance record distinguishes the existing mocked CLI failure test from
the live server authorization gate in issue
[#3140](https://github.com/ugoite/ugoite/issues/3140). A mock denial does not
prove that current Space membership is rechecked on a Remote continuation.

## Acceptance status

**Live Remote revocation: passed** on the source commit recorded below. Run
`scripts/test-sql-export-remote-auth.sh` against another checkout to repeat the
gate. The fixture creates a disposable Space, accepts a real Passkey invitation
as a viewer, approves a REST device credential, and exports through the real
`sql.query` route. A forward-only local HTTP proxy holds page two until the
owner revokes the viewer; the proxy forwards the request to the actual server
and does not generate or modify API responses.

Credential expiry is a separate, unverified case. No system clock is changed by
this harness; track it in [#3186](https://github.com/ugoite/ugoite/issues/3186).
The live revocation harness is tracked by
[#3185](https://github.com/ugoite/ugoite/issues/3185) under parent
[#3140](https://github.com/ugoite/ugoite/issues/3140). Do not include user
codes, credentials, continuation values, or private fixture data in future run
records.

## Pass criteria

- The viewer's approved REST device credential fetches page one for the
  immutable Space and SQL query.
- The owner revokes that viewer after the test barrier observes the page-two
  request. The unchanged request is then evaluated by the real server.
- Page two returns HTTP 403 with the server's existing `FORBIDDEN` code. The CLI
  exits nonzero, does not restart the query or switch Space/publication, commits
  no output file, cleans its temporary file, and does not print the opaque
  continuation.
- Failures during server startup, Passkey enrollment, device approval, or
  fixture setup are setup failures, not authorization passes.

The harness proves the tested server's live per-page membership check for this
fixture and request path. It does not prove credential expiration, every ACL
shape, or authorization behavior for other deployments.
