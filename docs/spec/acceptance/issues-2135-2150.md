## Retry and restart contract

The server does not claim that a response was durable merely because a client
received HTTP 2xx. A client that loses a mutation response must first read the
same immutable target and compare its content/revision. Repeating an Entry
create with the same ID is not an idempotency-key protocol; it is a signal to
reconcile the existing target. Repeating an Entry update with the old parent
revision remains a conflict. No adapter may turn that conflict into a silent
overwrite.

Browser sessions are server-side records. Restart preservation therefore means
preserving the configured Node control-store prefix and node secret, not
persisting credentials in the Browser. A damaged or absent control store is an
authentication/recovery event and must not be confused with a missing Space.
