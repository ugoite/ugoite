title: "v0.1 Foundation release"
---

**Status:** in progress

v0.1 is a Foundation Freeze, not a claim that every future Knowledge
application is complete. The release freezes the ownership, authority, history,
and adapter boundaries that later capabilities must preserve.

The detailed compatibility promise is the [v0.1 Knowledge compatibility
floor](v0.1-knowledge-compatibility.md). It freezes Knowledge semantics, not
the current physical encoding of the Catalog Head or other implementation
details. The canonical semantic fixture and its regression test are part of
that promise.

These boundaries govern lower-level product, runtime, adapter, and experience
choices. No implementation or experience preference may create a second
Knowledge source of truth or authority.

## Foundation boundary

- **Knowledge persists:** operator-owned Spaces are the durable source of truth.
- **Work may disappear:** Konase and other task runtimes may hold temporary
  context and execution state, but do not become Knowledge authority.
- **Knowledge can become tools:** future Views and task-specific applications
  may be Space-owned definitions rendered by adapters, without a second system
  of record.

## Implemented foundation

- 12-crate Rust workspace and Deno frontend/docsite/e2e workspace;
- operator-owned Space storage, append-only revisions, Forms, assets, search,
  saved SQL, and SQL sessions;
- local CLI core mode and remote CLI mode;
- Axum REST server, server-backed browser, and the MCP v1 semantic facade;
- one non-root runtime image, Compose files, Helm chart, and local
  release-validation task;
- versioned release publication with checksummed CLI/Compose assets and a
  post-publication browser/CLI quick-start gate;
- v0.1 supports mandatory browser authentication with Passkey/WebAuthn, opaque
  sessions, owner-approved Space access recovery, Remote CLI device
  authentication, invitation-gated OIDC authentication/account linking,
  Space membership/ACL enforcement, authenticated MCP access, and authorized
  audit reads.
- Recovery-code + recovery-TOTP Account Self-Recovery is supported after the
  user explicitly enrolls recovery protection. Administrator recovery,
  managed service-account operations, audit CRUD, and remote CLI
  asset upload remain future/reference work.
- Node and Space audit history is append-only portable state. The current REST
  surface exposes bounded, authorization-checked read-only audit listing; it
  does not expose audit-event mutation or CRUD.

## Remaining release work

The remaining v0.1 work is release completion and supported-release
communication, not a general application builder or Knowledge-to-tools runtime.
The release is accepted when:

- Knowledge authority and the portable Space model are explicit;
- append-only publication/history and Change/Run/Undo semantics are preserved;
- the v0.1 Knowledge compatibility floor and canonical fixture are preserved;
- adapters, Konase Work, and Experience runtime do not become authority;
- the release/distribution path is reproducible; and
- current and future documentation agree.

Knowledge-to-tools renderers, View DSLs, Application Definition schemas, and
arbitrary code execution are not v0.1 acceptance criteria.
