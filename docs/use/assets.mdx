Assets are Space-owned files referenced by Entries. Upload stores bytes only
and never attaches them to an Entry; a Form-owned Entry reference connects
the file to Knowledge. Upload and delete are available from core mode and
authenticated remote modes.

## Outcome

An uploaded file is stored as a Space Asset, attached through an Entry field,
and can be deleted by ID.

## Before you begin

Open the Space from [Spaces](spaces.mdx). For remote upload, sign in with a
credential that is authorized to mutate that Space.

## Steps

<Tabs>
<TabItem label="Browser">

1. Open the Entry that should reference the file.
2. Open the Entry's asset field to upload `./diagram.png`.
3. Confirm the Asset appears on the Entry.

</TabItem>
<TabItem label="CLI">

```bash
# Selected context
ugoite asset upload ./diagram.png
ugoite asset delete asset-id

# Backend or API mode, using the immutable Space UID
ugoite asset upload 019f1234-5678-7abc-8def-0123456789ab ./diagram.png
ugoite asset delete 019f1234-5678-7abc-8def-0123456789ab asset-id
```

Use `--filename` to choose the logical filename where the selected command
supports it. There is no dedicated attach flag: to attach, place the
returned asset object (`asset_id`, `name`, `media_type`, `size_bytes`,
`sha256`) as the field value through `entry create --fields-file` or
`entry update --fields-file`; `--field KEY=VALUE` stays a string and cannot
carry an asset object. An uploaded-but-unreferenced object is not
Space-visible Knowledge and never appears in `asset list`. Run
`ugoite asset --help` and `ugoite entry create --help` for exact flags and
mode requirements.

</TabItem>
</Tabs>

## Verify the result

The Asset ID resolves from the Space and the Entry reference opens the file.

## What became durable?

The Asset bytes and reference. Upload progress and previews are runtime
state.

## If it fails

- Upload rejected in a remote mode: confirm the immutable Space UID and the
  authenticated credential's Space mutation permission.
- Unsafe filename: the server applies safe-basename rules; retry with
  `--filename`.
