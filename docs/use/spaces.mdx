A Space is the ownership and storage boundary. Create it once, then open or
switch to it from any surface.

## Outcome

A durable Space exists and reopens with identical compatibility semantics on
Browser and CLI.

## Before you begin

Decide the address. Core mode takes a local path such as
`/path/to/workspace/spaces/demo`. Backend mode takes the immutable Space UID
returned by the server, such as
`019f1234-5678-7abc-8def-0123456789ab`.

## Steps

<Tabs>
<TabItem label="Browser">

1. Sign in with a registered Passkey.
2. Open the Space switcher and create a Space named `demo`.
3. Select `demo` and confirm the dashboard loads.
4. To switch, reopen the switcher and choose another Space.

</TabItem>
<TabItem label="CLI">

```bash
ugoite config set --mode core
ugoite space create /path/to/workspace/spaces/demo
ugoite space create /path/to/workspace/spaces/team-notes --name "Team Notes"
ugoite space get /path/to/workspace/spaces/demo
ugoite space list /path/to/workspace
```

The positional slug is the stable Space key. `--name` seeds the durable
display name only on first creation: omit it to default to the slug, and pass
a non-empty value otherwise (a whitespace-only name fails before any write).
Retrying `space create` for an existing Space converges to the same durable
identity and never renames it.

In backend mode, pass the immutable Space UID and omit the workspace path. A
human Space slug is creation metadata, not a remote identity. See the [CLI
Reference](../reference/cli.md).

</TabItem>
</Tabs>

## Verify the result

Reopen the Space across process and session boundaries and confirm the same
Space reads back identically.

## What became durable?

The Space directory with its Forms, Entries, Assets, saved SQL, Changes, and
portable history. The switcher selection is runtime state.

## If it fails

- Space not found: check local path versus immutable Space UID for the active
  endpoint mode.
- Remote create rejected: a node-admin human presence is required; plain token
  identities are rejected.
