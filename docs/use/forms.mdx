A Form defines the fields and defaults available when creating Entries. Use
short text, number, or date fields for values that should sort, filter, or
validate predictably. Use a Markdown field for longer notes, lists, links, and
formatted prose.

## Outcome

A `Meeting` Form exists with equivalent schema semantics on Browser and CLI.

## Before you begin

Open the Space from [Spaces](spaces.mdx).

## Steps

<Tabs>
<TabItem label="Browser">

1. Open **Forms** and create a Form named `Meeting`.
2. Add a short text field and a Markdown field.
3. Save and confirm the Form appears in the Forms list.

</TabItem>
<TabItem label="CLI">

```bash
ugoite form list
ugoite form list-types
ugoite form save meeting.json
ugoite form get Meeting
```

Run `ugoite form <command> --help` for the exact JSON shape of the installed
version.

With `-o json`, `form save` keeps the Form name in `id` and adds the persisted
`form_id`, `form_version`, and `applied` result. A committed save includes its
actual `change_id`; a no-op has `applied: false` and `change_id: null`. When a
remote server predates these receipt headers, the CLI reports
`identity_unverified: true` rather than guessing the Form or Change identity.

</TabItem>
</Tabs>

## Verify the result

List Forms and confirm `Meeting` reads back with the fields just defined.

## What became durable?

The Form definition in the Space. Form previews and open editors are runtime
state.

## If it fails

- Unknown field type: run `ugoite form list-types` and use a supported type.
- Validation error: check required fields and defaults, then retry.
