An Entry is a durable Knowledge object that follows its Form. It has no
intrinsic title: the stable `entry_id` is the identity, and a human-readable
name exists only when the Form defines it as a normal field. Updates append
revisions rather than rewriting old history.

## Outcome

An Entry exists with create plus edit revisions under identical validation
semantics on Browser and CLI.

## Before you begin

Create the Space in [Spaces](spaces.mdx) and the Form in [Create a
Form](forms.mdx).

## Steps

<Tabs>
<TabItem label="Browser">

1. Open **Forms**, select the `Meeting` Form, and choose **New Entry**.
2. Fill the typed fields.
3. Choose **Save entry** and confirm the saved status.
4. Edit the Entry, save again, and open **History** to confirm two revisions.

</TabItem>
<TabItem label="CLI">

```bash
ugoite entry create /path/to/workspace/spaces/demo meeting-2026-09-12 \
  --form Meeting --field Notes=Agenda
ugoite entry get /path/to/workspace/spaces/demo meeting-2026-09-12
ugoite entry history /path/to/workspace/spaces/demo meeting-2026-09-12
```

The H1 heading in raw Markdown carries only the 0.1.x legacy compatibility
title; entries created without one are title-less, and `--title` is a legacy
compatibility option (removed in 0.2). Existing title-bearing entries keep
their titles without migration.

Updates accept `--parent-revision-id` for optimistic conflict checks. A stale
parent conflicts instead of overwriting. `entry delete` appends a deletion
tombstone; permanent removal is unavailable. Run `ugoite entry <command>
--help` for exact flags.

Structured authoring (`--form` with `--field KEY=VALUE` or `--fields-file`)
goes through the same shared validation as raw Markdown. Supply each field
once: a key in both structured fields and preserved extra attributes (or an
extra shadowing a real field name) is rejected with
`{"code": "INVALID_INPUT", "detail": {"duplicate_fields": [...]}}`, where the
array is lexically sorted and message text is not contract.

</TabItem>
</Tabs>

## Verify the result

History shows create and edit as append-only revisions without rewriting
prior content.

## What became durable?

The Entry and its revision chain. Render caches and open editors are runtime
state.

## If it fails

- Entry rejected: check the Form name in frontmatter and typed field values.
- Revision conflict: re-read history and retry against the newest revision.
