Search finds durable Entries under identical keyword conditions on every
surface. Structured field conditions narrow the same Entry set without
becoming a second authority. Saved SQL and expert query live in
[Saved SQL and expert query](sql.mdx).

## Outcome

A keyword search returns the updated Entry, and a structured field filter
narrows to the same Entry set on Browser and CLI.

## Before you begin

Create an Entry in [Create and Edit Entries](entries.mdx).

## Steps

<Tabs>
<TabItem label="Browser">

1. Open **Search** and run a keyword search for `planning`.
2. Open the result to return to the Entry detail page.
3. Switch to **Advanced search**, pick a Form, and add a typed field
   condition such as `Status equals planning`. Results appear inline;
   no SQL is involved.

</TabItem>
<TabItem label="CLI">

```bash
ugoite entry list --text planning
ugoite entry list \
  --form Meeting --filter status:eq=planning --limit 20
```

`entry list --filter` accepts repeatable `FIELD[:OPERATOR]=VALUE` conditions
through the shared structured Search path, so the browser and CLI narrow to the
same Entry set. For saved definitions and read-only SQL, use
[Saved SQL and expert query](sql.mdx).

</TabItem>
</Tabs>

## Verify the result

The updated durable Entry appears in keyword results and in the structured
filter results on both surfaces.

## What became durable?

Nothing new. Search indexes are derived and replaceable.

## If it fails

- Search missing the change: confirm the Entry saved, then rerun the keyword
  search.
- Structured filter rejected: check the Form name and logical field names.
